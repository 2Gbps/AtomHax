Architecture · Core

Overview

AtomHax includes a native client extensibility pipeline that executes standard JavaScript files directly inside the client runtime. Scripts run locally in your dedicated session with zero external latency and direct access to game telemetry and client lifecycle events.

The client extension ecosystem is engineered for tournament referees, league statistics tracking, custom head-up displays (HUD), macro assistants, and Discord Rich Presence broadcasters without altering game physics or server trust boundaries.

Local Execution Sandbox: Extensions execute client-side with native permissions in your client environment. Scripts operate on standard Web APIs and the secure Electron preload bridge.
Specification · File Format

Script Anatomy & Metadata

Every extension is a clean .js file containing an optional userscript header block. The AtomHax Script Manager inspects this header to display the extension name, version, and execution target inside the client sidebar.

extension-header.js 
// ==UserScript==
// @name         Match Telemetry HUD
// @version      1.2.0
// @description  Renders live ball velocity and match clock on a glass canvas badge.
// @noframes     false
// ==/UserScript==

(function () {
  'use strict';

  // Single-initialization guard
  if (window.__telemetryHudLoaded) return;
  window.__telemetryHudLoaded = true;

  // Extension logic executes here
})();
Header Directive Type Behavior & Purpose
@name string Display name presented in the client settings and scripts manager drawer.
@version string Semantic version string for extension tracking and updates.
@description string Brief description of the extension capabilities.
@noframes boolean When true, executes in the top-level Electron renderer shell. When omitted or false, executes inside the game frame with direct canvas access.

Client API · Preload Bridge

Desktop Client API · window.electronAPI

The desktop client exposes a secure IPC bridge on window.electronAPI. This bridge allows extensions to inspect and persist preferences, trigger Discord RPC updates, generate cryptographic player identifiers, and manage extension files.

Method Signature Return Type Description
getAppPreferences() Promise<AppPreferences> Returns stored client configurations (FPS uncap, render scaling, shortcuts, discord RPC).
setAppPreference(key, value) Promise<boolean> Persists a specific user preference key in preferences.json.
updateDiscordRPC(details) void Updates the client Discord Rich Presence status string in real time.
generatePlayerAuthKey() Promise<string> Generates or retrieves the ECDSA P-256 cryptographic auth key identifying your player profile.
exportPreferencesFile() Promise<{success: boolean}> Exports application configuration backup to disk.
importPreferencesFile() Promise<{success: boolean}> Opens file dialogue to restore saved preferences.
scriptsList() Promise<NyxScript[]> Returns array of installed scripts with {id, name, content, enabled}.
scriptsToggle(id) Promise<{success, enabled}> Enables or disables an installed extension.
reloadGameframe() void Gracefully reloads the gameframe to apply newly activated scripts without client restart.
Telemetry · Read-Only State

Match Telemetry State · window.__hb.state()

Inside the gameframe, window.__hb.state() provides a zero-overhead, read-only snapshot of current match telemetry. Polling this method is completely non-intrusive and safe for high-frequency render loops.

read-telemetry.js 
const snap = window.__hb ? window.__hb.state() : null;

if (snap && snap.ok) {
  console.log(`Room: ${snap.roomName} | Phase: ${snap.phase}`);
  console.log(`Score: Red ${snap.scoreRed} — ${snap.scoreBlue} Blue`);
  if (snap.ball) {
    const speedKmH = (Math.hypot(snap.ball.vx, snap.ball.vy) * 3.6).toFixed(1);
    console.log(`Ball Speed: ${speedKmH} km/h`);
  }
}
Field Property Type Description
ok boolean true when currently connected to an active room with loaded stadium state.
roomName string | null Name of the current room.
phase 'lobby' | 'countdown' | 'playing' | 'stopped' Current lifecycle phase of the match.
myId number Local player ID allocated by the room host.
scoreRed / scoreBlue number Current goal counts for Red and Blue teams.
timeLimit / scoreLimit number Configured room limits in minutes and goals.
elapsed number Total elapsed match time in seconds.
locked boolean Whether team switching is locked by the room administrator.
ball { x, y, vx, vy, r } | null Ball coordinates, velocity vector components, and radius in stadium units.
players PlayerSnapshot[] Array of all player descriptors: { id, name, team, admin, kicks, country, avatar, playing, pos, vel }.
Events · Reactive API

Event Subscriptions · window.__hb.on()

Subscribe to real-time room events without polling the DOM. Handlers are invoked immediately when the underlying engine processes incoming network packets.

Event Name Callback Payload Trigger Condition
'goal' { team: 'red' | 'blue' } Fired whenever a goal is validated by the referee engine.
'matchEnd' { team: 'red' | 'blue' } Fired when the match concludes via time expiration or score limit.
'chat' { player: number, name: string, msg: string } Fired when any player sends a public message.
'whisper' { player: number, name: string, msg: string } Fired when a private direct message is received.
'join' { player: number, name: string } Fired when a new user enters the room.
'leave' { player: number, name: string, reason, banned, by } Fired when a user leaves, is kicked, or is banned.
'gameStart' { by: string | null } Fired when an administrator kicks off the game.
'gameStop' { by: string | null } Fired when an administrator halts the game.
'pause' { by: string | null, paused: boolean, countdown: boolean } Fired when match play is paused or resumed.
'teamMove' { by, player, name, team: 'red' | 'blue' | 'spec' } Fired when a player changes team slots.
'adminChange' { by, player, name, admin: boolean } Fired when admin rights are granted or revoked.

Admin · Quality of Life

Room Administration & Actions

For room owners, tournament organizers, and community hosts, window.__hb provides safe, programmatic wrappers around standard room management actions:

Method Signature Return Type Description
__hb.chat(message) boolean Sends an in-game chat message to the room. Returns true if delivered.
__hb.join(team) boolean Moves local user to 'red', 'blue', or 'spec'.
__hb.leave() boolean Safely exits the current room and transitions back to the lobby.
__hb.admin.start() boolean Starts match play if host privileges are present.
__hb.admin.stop() boolean Stops active match play.
__hb.admin.pause() boolean Toggles pause / resume state.
__hb.admin.auto() boolean Toggles automated team balancing.
__hb.admin.random() boolean Randomly shuffles players into Red and Blue teams.
__hb.admin.reset() boolean Resets room match statistics and scores.
__hb.admin.lock() boolean Locks or unlocks team slots to prevent unapproved joining.

Production Implementation Examples

Example 1: Liquid Glass Ball Speed HUD

Builds a glass telemetry pill in the bottom-left corner of the gameframe that renders real-time ball velocity in km/h. It consumes the documented window.__hb API when present and otherwise captures the engine directly, so older client builds are covered too:

ball-speed-hud.user.js 
// ==UserScript==
// @name         Ball Speed HUD
// @version      1.3.0
// @description  Glass pill with the real-time ball speed, bottom-left. Uses the documented window.__hb API when present, otherwise captures the engine directly.
// @noframes     false
// ==/UserScript==

(function () {
  'use strict';
  if (window.__ballSpeedHud) return;
  window.__ballSpeedHud = true;

  const TICK_MS = 40;          // render/poll cadence
  const PILL_LEFT = 12;        // gameframe-local inset from the left edge
  const BOTTOM_FALLBACK = 48;  // used when the game's bottom bar cannot be measured
  const MEASURE_EVERY = 25;    // re-measure the bottom bar every ~1s

  // ── Glass pill ──
  // Same material recipe the client applies to HaxBall's own fps/ping stats
  // view: gradient fill, hairline border, inset top highlight, hard text
  // shadow. Pill silhouette instead of the stats view's rounded rectangle.
  // No backdrop-filter — it blurs the gameplay underneath and forces an
  // extra GPU compositing layer over the canvas. Nothing here animates, so
  // the pill only repaints when the number changes.
  const pill = document.createElement('div');
  pill.style.cssText = `
    position: fixed;
    left: ${PILL_LEFT}px;
    bottom: ${BOTTOM_FALLBACK}px;
    z-index: 9999;
    display: none;
    align-items: center;
    gap: 7px;
    padding: 5px 12px;
    border-radius: 999px;
    background: linear-gradient(135deg, rgba(27,33,37,0.85) 0%, rgba(27,33,37,0.7) 50%, rgba(27,33,37,0.8) 100%);
    border: 1px solid rgba(255,255,255,0.12);
    box-shadow: 0 4px 16px rgba(0,0,0,0.3), inset 0 1px 0 rgba(255,255,255,0.08);
    font-family: monospace;
    font-size: 12px;
    line-height: 1;
    color: #f0f4f8;
    text-shadow: 1px 1px 1px #000, 0 1px 1px #000;
    pointer-events: none;
    white-space: nowrap;
  `;

  const liveDot = document.createElement('span');
  liveDot.style.cssText = `
    flex: 0 0 auto;
    width: 6px;
    height: 6px;
    border-radius: 50%;
    background: #6fe88a;
    box-shadow: 0 0 6px rgba(111,232,138,0.9);
  `;

  const speedLabel = document.createElement('span');
  speedLabel.textContent = '0.0 km/h';

  pill.appendChild(liveDot);
  pill.appendChild(speedLabel);

  // ── Engine capture (clients without window.__hb) ──
  // Old client builds predate interact-bridge.js, so the documented API is
  // not there. Read the ball straight from the engine instead. The engine is
  // minified, so both channels match on shape, never on a fixed object graph:
  //
  //   bind — the client binds methods to objects at join time; the room is
  //          the object carrying ta() + T.K (player list) + a numeric yc.
  //   push — the world spawns bodies through Array.prototype.push into an
  //          array of {a, G, V} objects (position, velocity, radius); the
  //          ball is entry 0. This channel self-heals across room changes
  //          because a rebuilt world is a new array.
  //
  // Both hooks are passive, guarded, and settle to near-zero cost once the
  // references are held.
  let capturedRoom = null;
  let capturedBodies = null;

  (function hookBind() {
    const originalBind = Function.prototype.bind;
    if (originalBind.__ballSpeedHudHook) return;
    originalBind.__ballSpeedHudHook = 1;
    Function.prototype.bind = function (thisArg) {
      const bound = originalBind.apply(this, arguments);
      try {
        if (thisArg && typeof thisArg === 'object' &&
            thisArg.T && Array.isArray(thisArg.T.K) &&
            typeof thisArg.yc === 'number' && typeof thisArg.ta === 'function') {
          if (capturedRoom !== thisArg) capturedRoom = thisArg;
        }
      } catch (e) {}
      return bound;
    };
  })();

  (function hookPush() {
    const originalPush = Array.prototype.push;
    if (originalPush.__ballSpeedHudHook) return;
    originalPush.__ballSpeedHudHook = 1;
    Array.prototype.push = function (element) {
      try {
        if (element && typeof element === 'object' &&
            typeof element.V === 'number' && element.a && element.G) {
          if (capturedBodies !== this) capturedBodies = this;
        }
      } catch (e) {}
      return originalPush.apply(this, arguments);
    };
  })();

  const readDirectBall = () => {
    let bodies = capturedBodies;
    if (!bodies && capturedRoom && capturedRoom.T) {
      const game = capturedRoom.T.M;
      bodies = game && game.va ? game.va.H : null;
    }
    if (!bodies || !bodies.length) return null;
    const ball = bodies[0];
    if (!ball || !ball.a || !ball.G) return null;
    return { vx: ball.G.x, vy: ball.G.y };
  };

  // ── Telemetry source selection ──
  // Prefer the documented bridge. Sticky once it produces one ok snapshot:
  // from then on its phase gating is authoritative. Until (or unless) it
  // does, read the engine directly.
  let hbUsable = false;

  const readHbSnapshot = () => {
    const bridge = window.__hb;
    if (!bridge || typeof bridge.state !== 'function') return null;
    try {
      const snapshot = bridge.state();
      return snapshot && snapshot.ok ? snapshot : null;
    } catch (e) {
      return null;
    }
  };

  // ── Rendering state ──
  let visible = false;
  let lastSpeedText = '';
  let tickCount = 0;
  let bottomOffset = BOTTOM_FALLBACK;

  const setVisible = (on) => {
    if (visible === on) return;
    visible = on;
    pill.style.display = on ? 'flex' : 'none';
  };

  // Sit the pill directly above the game's bottom UI band (chat + the native
  // stats view where the fps counter lives). Measured from the live layout
  // instead of hardcoded, so it holds in every chat mode and window size.
  const measureBottomOffset = () => {
    const bottomBar = document.querySelector('.bottom-section');
    const viewportHeight = window.innerHeight;
    let offset = BOTTOM_FALLBACK;
    if (bottomBar) {
      const bounds = bottomBar.getBoundingClientRect();
      if (bounds.top >= viewportHeight * 0.45) {
        offset = Math.round(viewportHeight - bounds.top) + 10;
      }
    }
    if (offset !== bottomOffset) {
      bottomOffset = offset;
      pill.style.bottom = offset + 'px';
    }
  };

  const tick = () => {
    tickCount += 1;

    const snapshot = readHbSnapshot();
    if (snapshot) hbUsable = true;

    let ball = null;
    if (hbUsable) {
      ball = snapshot && snapshot.phase === 'playing' ? snapshot.ball : null;
    } else {
      try {
        ball = readDirectBall();
      } catch (e) {
        ball = null;
      }
    }

    if (!ball) {
      setVisible(false);
      return;
    }

    if (!pill.isConnected && document.body) document.body.appendChild(pill);
    if (!visible || tickCount % MEASURE_EVERY === 0) measureBottomOffset();

    const speedKmH = (Math.hypot(ball.vx, ball.vy) * 3.6).toFixed(1);
    const speedText = `${speedKmH} km/h`;
    // Write only on change; textContent on one span, never innerHTML — no
    // re-parse, no style recalc beyond the changed text node.
    if (speedText !== lastSpeedText) {
      speedLabel.textContent = speedText;
      lastSpeedText = speedText;
    }
    setVisible(true);
  };

  setInterval(tick, TICK_MS);
  tick();
})();

Example 2: Automated Tournament Referee & Welcome Bot

Listens for player connections, broadcasts welcoming messages, monitors match goals, and announces final results upon match conclusion:

tournament-referee.user.js 
// ==UserScript==
// @name         Tournament Referee Bot
// @version      1.0.0
// @description  Automated match announcements and welcome greetings.
// ==/UserScript==

(function () {
  'use strict';
  if (window.__tournamentRef) return;
  window.__tournamentRef = true;

  const boot = () => {
    if (!window.__hb) return setTimeout(boot, 250);

    // Welcome connecting players
    window.__hb.on('join', ({ name }) => {
      window.__hb.chat(`Welcome to the lobby, ${name}!`);
    });

    // Announce match goal tally
    window.__hb.on('goal', ({ team }) => {
      const s = window.__hb.state();
      if (s) {
        window.__hb.chat(
          `[GOAL] ${team.toUpperCase()} scores! Current Score: Red ${s.scoreRed} — ${s.scoreBlue} Blue`
        );
      }
    });

    // Announce match conclusion winner
    window.__hb.on('matchEnd', ({ team }) => {
      window.__hb.chat(`[MATCH OVER] Victory goes to the ${team.toUpperCase()} team! Well played.`);
    });
  };

  boot();
})();

Example 3: Dynamic Discord RPC Score Syncer

Bridges in-game match state to Discord Rich Presence using the top-level Electron API:

discord-score-syncer.user.js 
// ==UserScript==
// @name         Discord Rich Presence Syncer
// @version      1.0.0
// @description  Syncs active match scores to Discord client presence.
// ==/UserScript==

(function () {
  'use strict';
  if (window.__discordSyncer) return;
  window.__discordSyncer = true;

  setInterval(() => {
    const api = window.electronAPI || (window.parent && window.parent.electronAPI);
    if (!api || !window.__hb) return;

    const s = window.__hb.state();
    if (s && s.ok && s.phase === 'playing') {
      const msg = `Playing ${s.roomName || 'Match'} | Red ${s.scoreRed} - ${s.scoreBlue} Blue`;
      api.updateDiscordRPC(msg);
    } else {
      api.updateDiscordRPC('In Lobby • AtomHax v0.5.4');
    }
  }, 3000);
})();
Standards · Best Practices

Lifecycle, Timing & Safety Guidelines

When developing extensions for the AtomHax client, follow these engineering standards to maintain high stability and smooth performance:

1. Guard Against Duplicate Injections: Scripts re-evaluate when moving between rooms or replays. Protect global event listeners by checking an initialization flag like if (window.__myScriptActive) return; at the top of your file.
2. Do Not Block Native Typing: When capturing keyboard shortcuts, ensure the user is not actively typing inside chat or room input fields by checking document.activeElement.tagName === 'INPUT'.
3. Observe DOM Rebuilds: HaxBall reconstructs portions of its DOM when transitioning between views. Use a MutationObserver or recurring interval when binding custom DOM elements to avoid losing UI nodes.
